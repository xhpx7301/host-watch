# HostWatch 服务器库存监控

[GitHub 仓库](https://github.com/xhpx7301/host-watch)

自托管的多厂商库存监控与补货抢购辅助工具。支持 VMISS、VPS.SOY、Akile、Isvoro、DMIT、搬瓦工专用库存解析和通用公开 HTTPS 商品页；每轮补货通过 Telegram 发送一次提醒与人工购买入口，后续库存变化更新原消息。VPS 补货抢购可在明确支持的商家接口上创建待付款订单，永远不会自动付款；不支持的站点使用手动购买链接。

网页、Telegram、运行日志和定时备份时间统一使用北京时间（Asia/Shanghai，UTC+08:00），不受服务器或浏览器本地时区设置影响。

VMISS 曾对自动化访问返回拦截页。请先确认目标厂商允许自动检查及访问频率。遇到 HTTP 403、429 或安全验证页时，程序会记录状态、尝试告警并停止，不会自动重试。FlareSolverr 仅适用于你拥有或明确获准测试的站点，默认关闭。检查间隔可自定义到秒，0 表示本轮检查完成后立即检查下一轮。

## 支持的监控方式

- **VMISS WHMCS**：解析商品卡片和库存数量，可生成 `aff.php` 推广入口。
- **VPS.SOY**：按完整套餐名称匹配商品卡片，识别库存及购买入口，支持深港IX-MINI 等套餐；负库存按缺货处理。
- **Akile**：读取商店使用的公开商品接口，按线路及完整套餐名称自动识别地区，也可指定地区区分重名商品。默认添加中国台湾 TWLite-Mini，抢购可自动创建待付款订单。
- **Isvoro**：按类型、地区/线路、套餐三个 ID 校验归属，读取公开目录和商品详情中的实时库存及 IP 可用状态，支持三层下拉选择和刷新目录。
- **DMIT**：读取公开价格页和分类页，按独立商品 PID 匹配；展示地区、线路、配置、网络及价格，按明确库存数量或库存状态监控补货，购买入口使用可修改的 AFF（默认 `22544`）。
- **搬瓦工**：读取公开 `https://bwh81.net/order/catalog.json` 目录，按套餐类型、中文地区 / 机房和计费周期精确匹配，区分每个计费周期的价格及库存；购买入口使用可修改的 AFF（默认 `84938`）。
- **通用 HTTPS 网页**：配置 CSS 库存元素选择器，支持提取数量或匹配有货/缺货文本；购买入口可单独设置，留空时使用商品页。

所有适配器均支持普通 HTTPS、FlareSolverr 浏览器请求和 cloudscraper 请求。普通请求解析服务器返回的 HTML；浏览器请求可执行 JavaScript，并配置渲染等待读取动态库存。这些方式均不登录厂商账户；复杂交互和私有 API 仍需专用适配器。常规库存提醒只提供购买入口；VPS 补货抢购的自动模式仅在显式适配时创建待付款订单，付款仍由用户在官网完成。

## 库存监控、库存通知与库存大盘

导航顺序为运行概览 → VPS 库存大盘 → VPS 库存监控 → VPS 库存通知 → VPS 补货抢购 → Akile 交易市场 → 独角鲸云 → 网页请求 → AFF 管理 → 设置。

库存大盘中的 Akile 默认展示全部套餐，支持地区、节点筛选、节点名称搜索和跨地区的套餐搜索。节点选项显示套餐数量，点击“查看全部套餐 / 重置筛选”恢复全目录。同名节点按地区和节点 ID 区分，套餐可分别加入库存监控或 Telegram 补货通知。筛选使用同一份全量快照，不重复请求商家；Akile 全目录也支持大盘自动刷新。

搬瓦工使用地区、机房筛选，默认读取全部报价；同名机房按机房 ID 区分，不同计费周期分别列出。支持搜索机房 ID、名称和配置，并支持全目录自动刷新。DMIT 使用地区、网络类型、处理器平台筛选；完整配置套餐显示在下方列表，平台沿用官网 AS3、AN4、AN5 等标识，未提供的平台明确标注。DMIT 网络和处理器筛选使用当前地区快照，地区切换优先读取缓存；全地区仅手动刷新，单地区支持自动刷新并继续校验购买页库存。两者均可一键重置，并将指定配置套餐加入监控或通知。

“独角鲸云”默认展示全部公开套餐，使用地区、商品/实例筛选；地区显示中文名与实例、套餐数量，实例支持名称或 ID 搜索。也可不选地区或实例，直接跨全目录搜索套餐、实例、地区或配置，并筛选库存。点击“查看全部套餐 / 重置筛选”恢复全目录。地区与实例切换使用同一次读取的全量快照，支持全目录自动刷新。可将指定套餐加入库存监控或 Telegram 库存通知；规则按实例 ID 和套餐 ID 精确匹配，套餐下架时保留规则，恢复上架后继续监控。目录读取不需要独角鲸云账户凭据。

AFF 管理同时支持每个商家的默认通知优惠码；商品编辑器中的“通知优惠码”可覆盖商家默认值。Telegram 消息使用可点击复制的代码格式显示优惠码。库存大盘点击“调整商家顺序”后可直接拖动顶部商家按钮，点击“保存商家顺序”退出编辑，再保存库存监控卡片即可同步到目录、筛选器和商品添加窗口。

页面的开关与选择均使用状态按钮，点击切换、再次点击取消；支持键盘 Enter / 空格。每个可编辑卡片都有独立保存按钮，运行、检查和启停操作立即执行；大盘商品选择仅用于本次批量操作，全选按钮区分未全选、部分选中和已全选。

管理页采用紧凑布局：概览直接展示已关注商品的最近库存，商品表格集中显示配置、带宽、价格和状态；蓝色用于主要操作及价格，紫色用于购买入口，红绿灯表示服务和库存状态。多种计费周期可点击价格展开，编辑、移出和监控列表的“加入库存通知”收在“更多”中，测试与停止测试保持直接可用。检查间隔等设置和使用说明可按需展开；手机端商品表格可横向滑动查看。

监控、通知和大盘表格的表头及内容居中显示，流量与带宽采用 `流量@带宽`（例如 `500GB@1Gbps`），缺失字段不补造。网页价格统一显示货币符号，如人民币 `¥`、美元 `$`、加元 `CA$`、港币 `HK$`、日元 `JP¥`、欧元 `€`，保留原金额和计费周期；外币价格下方显示人民币参考折算。汇率使用 Frankfurter 日频公开数据，以人民币为基准每天最多更新一次，缓存最近成功结果；顶部显示北京时间、数据日期和商品实际使用到的币种汇率。汇率只用于估算，实际价格以商家结算页为准；未知币种保留原文。库存监控的线路由管理员分别填写“电 / 联 / 移”，以绿、蓝、紫标签显示并统一保存；升级前的线路文本保留为“原线路”，可编辑或清空。

库存监控与库存通知均可拖动商家旁的 `⠿` 手柄上下排序，支持鼠标和触摸；也可聚焦手柄后用 `↑` / `↓` 调整，拖动时按 Esc 取消。两份列表独立保存顺序，调整后分别保存库存监控或库存通知卡片；商家总顺序保存到库存监控卡片。监控筛选期间仅调整可见商品所在的位置，隐藏商品的位置保持不变；未自定义顺序时沿用商家顺序，新加入且尚未排序的商品列在已排序商品之后。排序只影响网页展示。

商家、地区 / 线路、搜索、库存筛选及大盘翻页使用短暂淡入过渡，高级商品的联动选择也有过渡反馈。快速切换不会叠加动画，后台定时刷新不会反复播放；系统开启“减少动态效果”时自动关闭过渡。

硬件配置统一以 `1C/0.5G/10GB` 单行展示 CPU、内存、硬盘（内存按 1024MB = 1G 换算），电 / 联 / 移标签与线路输入内容居中。流量与带宽使用 `@` 连接；Isvoro 从公开配置读取带宽并将 `ratelimit` 的 MB/s 换算为 Mbps，Akile 的零流量额度按官网含义显示“无限制”，缺失字段仍显示未知。

三网线路输入框随内容伸缩，标签紧邻线路文字，较长线路限制输入框宽度并可移动光标查看。升级后首次打开旧版 Isvoro 大盘快照会自动刷新当前分类，补齐带宽信息；刷新失败或停止时仍保留旧快照并给出提示，不修改已有监控配置。

VPS.SOY 的硬件配置只提取 CPU、内存、硬盘，流量与带宽单独展示；端口数量、虚拟化架构、网络说明及商家公告不混入配置标签。旧版已保存快照也按相同规则显示，无需删除商品后重新添加。

Isvoro 限时秒杀可在 **VPS 库存通知 → Isvoro 限时秒杀** 开启并保存配置。独立于普通商品，也支持仅开启秒杀监控；使用独立检查间隔、Isvoro 网页请求方式和 Telegram 配置。读取官网公开的 `/api/v1/seckill/activities`，发现预告或进行中的新活动即发送一次，附活动时间、优惠套餐、配置及带当前 AFF 的活动入口。已结束活动不提醒；同一活动 ID 在重启、暂时消失再出现、价格或库存变化后不重复提醒。关闭 Telegram 或发送失败不会将活动记为已通知，恢复后仍在进行或预告中的活动会再尝试发送。自动去重记录单独保存在库存状态文件旁的 `state-seckill.json`（自定义 `STATE_FILE` 时采用对应文件名前缀），更新程序时保留。

“测试秒杀通知”在暂停或未开启自动提醒时也可使用，会将当前活动或“暂无秒杀活动”发至已保存的 Telegram；页面显示单次测试结果，可停止，停止后不发送。测试不写入自动通知记录，自动监控仍会按规则通知一次。测试共用现有可终止的子进程和浏览器资源限制，同一时间只执行一个商品或秒杀测试。

Telegram 补货提醒使用分段消息：商品标题、地区与线路、管理员备注和三网线路（有填写时）、硬件配置、流量/带宽、带货币符号的价格、库存及最后成功检查时间，并提供带当前 AFF 的“立即购买”按钮与购买链接。每轮缺货转有货发送一次新消息，保存 bot/chat 对应的消息 ID；持续有货、数量增减只调用 `editMessageText` 更新原消息，售罄改为“❌ 售罄”，下一轮补货再发送新消息。库存变化在下一次成功检查后更新；无变化时最多每 60 秒编辑一次以刷新时间，避免短间隔检查反复调用 Telegram。读取失败或商品下架无法确认时，原消息标记“⚠️ 库存暂未确认”，保留最后成功检查时间和结果，恢复后更新，不把异常当作售罄。

消息记录与库存基线保存在 `state.json` 的商品 `telegram` 字段中，重启、更新及正常备份均保留；不存储 bot token。每条消息成功发送后立即保存记录，部分商品发送失败不会重复发送其他商品，失败任务在后续检查重试。原消息被删除或 Telegram 不允许编辑时显示提示，本轮不会额外发送替代消息，下轮补货发送新通知。更换 bot/chat 不会编辑原目标的消息。升级前的历史消息未保存消息 ID，无法追溯更新；将从升级后新发出的补货消息开始跟踪。暂停监控或移出通知后停止更新原消息。

单次测试仍单独发送测试结果，不编辑自动补货消息、不修改自动通知记录；明确标注测试、有货 / 缺货及耗时，接口错误单独标注测试失败。商品与管理员文本均转义后发送，关闭链接预览；暂停时仍可测试通知。

高级商品管理中的通知商品自动跟随库存通知的排序，其余自定义或已移出通知的商品列在后方；同步顺序时保留展开状态和填写内容。“加入库存监控”和“加入库存通知”为独立切换按钮，加入后分别显示绿色、紫色的“已加入”状态，再次点击可移出对应列表，分别保存对应卡片生效。

- **VPS 库存监控**：仅关注并查看自己选择的商品，不发送 Telegram，无需配置机器人也能运行。表格自动读取商家、产品名称、地区、硬件配置、流量/带宽、价格和库存；管理员手动填写备注和线路，统一保存。后台每轮检查使用同一份商品响应更新库存与配置，不额外扫描整个目录。直接购买跳转带当前 AFF 的商品入口，也可将该商品加入库存通知。监控、通知和库存大盘均可按默认顺序或月付人民币等值价格升序 / 降序排列，季付、半年付和年付自动折算为月均价格。
- **VPS 库存通知**：独立管理需要 Telegram 提醒的商品。与监控使用相同的商品信息表格，展示商家、产品名称、地区、硬件配置、流量/带宽、价格、状态和带 AFF 的购买入口，不含备注或线路编辑列。最近成功测试也会更新当前页面商品信息并标注测试时间，不写入后台库存历史。每轮补货推送一次，后续数量增减和售罄更新原消息。“测试通知”只检查当前商品一次并发送库存或错误结果，暂停时也可测试，可停止测试，不修改自动检查的库存历史。库存监控和库存通知分别设置自动/手动模式与检查间隔，也可分别点击手动刷新；概览会显示两者最近日志。设置修改后保存对应卡片，启停和测试按钮无需保存即可执行。
- **VPS 库存大盘**：浏览 VMISS、VPS.SOY、Akile、Isvoro、DMIT、搬瓦工的公开套餐目录，支持“全部公开套餐”或地区 / 线路分类筛选，分别提供“加入库存监控”和“加入库存通知”，支持批量加入与独立移出。两个选择互不影响，同一商品只检查一次；已成功读取全量目录后，切换分类会优先从服务器缓存筛选，不重复请求商家。Akile、独角鲸云和搬瓦工支持全目录自动刷新；其他商家的全部公开套餐只支持手动刷新，日常自动刷新建议选择单地区 / 单分类。

使用流程：大盘选择商家和分类 → 加入监控或通知 → 分别设置各模块的刷新方式与间隔 → 保存对应卡片。库存监控、库存通知和库存大盘各自独立刷新；只关注库存无需 Telegram，通知商品需要在 Telegram 通知栏目保存机器人及目标聊天。关闭网页后已启用的自动刷新仍继续检查。

高级手动管理支持保存目录未收录或暂时下架的商品。有效目录中找不到已选套餐或线路时，该商品显示“未知”及未匹配原因，保留原有配置和通知基线，其他正常商品继续检查；重新上架且仍匹配原有名称/ID 后自动恢复。未匹配也可能是表单填错，特别是 Akile 的线路名称与套餐名称必须分别填写。无法判断的响应、重复匹配、异常库存和访问拦截仍会明确报错，不被当作缺货。

默认新增通知首次检查只建立库存基线；开启“首次启用该商品通知时，有货也发送提醒”后，从仅监控转为通知且有货的商品也会提醒。重启服务不会重复推送。移出监控不取消通知，移出通知也不移出监控；从两份列表都移出才停止检查，商品配置和历史仍保留。升级时旧版启用商品同时保留在两份列表，保持原有关注及订阅，可分别移出。

大盘刷新只读取所选分类，不发送消息，不修改后台检查或通知历史。自动刷新提供手动、1/5/10 分钟选项，默认仅手动；设置保存到服务器配置，并且仅在大盘打开且网页可见时执行，使用已保存的商家请求方式，任务可以停止。缓存位于配置目录旁的 `catalog.json`，最多 64 个分类，每类 600 个商品；最多配置 100 个商品。来源无法提供的字段显示“—”，无法确认的库存显示未知，历史快照标注读取时间。价格和购买资格以商家下单页为准。

“AFF 管理”统一设置各商家推广码或完整推广链接，保存后应用于监控、大盘、通知与测试的购买入口；保留具体套餐参数，留空使用普通商品入口。大盘可调整商家顺序。各商家的后台检查和测试请求方式在“网页请求”统一设置。

## 一键安装

适用于 Debian 12/13，要求 systemd 和 root/sudo 权限。脚本会安装依赖、创建 `vmiss-monitor` 系统用户、自动部署 Docker 和官方 FlareSolverr 容器、安装程序和 systemd 单元，并启动仅监听 `127.0.0.1:8765` 的管理页。FlareSolverr 仅监听本机 `127.0.0.1:8191`，设置自动重启，启动后检测就绪状态。库存监控默认关闭，安装脚本不会启用或启动它。首次部署需要下载浏览器镜像，请预留内存、磁盘和到 ghcr.io 的网络连接；浏览器请求按商品顺序执行。

```sh
curl -fsSL https://raw.githubusercontent.com/xhpx7301/host-watch/main/install.sh | sudo bash
```

脚本可重复执行用于升级，已有的 `/var/lib/vmiss-monitor/config.json`、`/etc/vmiss-monitor.env` 和 `/etc/vmiss-monitor-admin.env` 会保留。

全新安装会自动创建管理页管理员 `admin`，使用每台服务器独立生成的随机密码，并在安装终端显示一次；认证文件仅保存密码哈希。请保存安装输出中的密码，遗失后可运行 `hw passwd` 重置。安装器保留已有账号、旧密码及自定义账号文件；旧版未配置账号的安装可运行 `hw init-admin` 补建，不会重置已有账号。

项目已更名为 HostWatch，仓库名为 `host-watch`。为兼容已部署版本，继续沿用 `vmiss-monitor` 安装目录、系统用户和 systemd 服务名，以及 `/etc/stockwatch-users.json`、`/var/backups/stockwatch/` 等数据路径；菜单快捷命令改为 `hw`。

## Debian 管理菜单

安装或升级完成后，在 Debian 12/13 终端运行：

```sh
hw
```

直接输入 `hw` 即可调出菜单；普通用户会自动通过 sudo 请求权限，root 无需 sudo。`host-watch` 命令也可调用同一菜单，原 `stockwatch` 命令继续兼容。菜单按“监控服务”“管理页服务”“更新与备份”“管理员账号”分成二级菜单，常用配置、更新、日志和账号操作也可在网页的“管理员管理”中完成。菜单还提供“完全删除 HostWatch”选项：输入 `DELETE HOSTWATCH` 二次确认后，会停止服务并删除程序、配置、库存历史、管理员账号、备份、快捷命令、HostWatch 创建的 FlareSolverr 容器及系统账号；不会卸载 Docker、Python 等共享依赖，也不会删除外部 FlareSolverr 容器。也可以直接执行：

旧版使用 `jk` 的服务器，重新执行一键安装后改用 `hw`；安装器会移除内容与本项目旧启动脚本完全一致的 `jk` 文件，不会删除其他同名脚本。

```sh
hw update       # 下载更新，先备份，再安装
hw backup       # 备份程序、配置和账号
hw status       # 查看服务状态
hw users        # 列出管理页用户
hw add-user     # 交互式添加用户
hw passwd       # 交互式修改密码
hw delete-user  # 交互式删除用户
hw init-admin   # 尚无认证时创建 admin 和随机密码，已有账号保持不变
hw admin-domain              # 兼容旧命令：检查账号并重启，已无需设置域名
hw uninstall   # 二次确认后从服务器完全删除 HostWatch
```

这里的用户是**管理页管理员**，都有完整配置权限，不是 Debian/SSH 系统账号。密码在终端中隐藏输入，不支持通过命令行参数传递。账号保存于 `/etc/stockwatch-users.json`，使用独立随机盐和 PBKDF2-SHA256 哈希，权限为 `root:vmiss-monitor 0640`。不能删除最后一个管理员。

首次创建账号后，菜单会将旧 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 配置替换为 `ADMIN_USERS_FILE`，保留域名等其他设置，并重启管理页。以后修改密码或删除账号后，旧凭据在下一次请求即失效。仅本机 SSH 隧道访问的旧安装可继续沿用原认证方式；域名反向代理必须配置账号或原有密码。

更新使用 GitHub `main` 的安装程序，保留商品、Telegram 和账号配置；成功后仅恢复更新前正在运行的监控服务。下载脚本发生网络超时等临时错误时最多尝试三次，最后一次使用 GitHub 官方备用入口；证书校验失败、HTTP 404 或内容格式异常直接停止，不关闭 TLS 校验、不使用第三方镜像。下载脚本失败发生在备份和停止服务之前，现有程序、配置和服务均不改动。进入安装阶段后失败则不会自动恢复监控，终端会输出备份路径。备份位于 `/var/backups/stockwatch/`，仅 root 可访问；其中包含配置凭据，应按敏感文件保管。备份不包含虚拟环境，恢复程序后可重新安装依赖。菜单不提供自动恢复操作。

首次使用时，在管理页配置商品，分别选择库存监控和库存通知的自动刷新方式，点击各自卡片的保存按钮应用。两个模块都设为仅手动刷新时，HostWatch 自动检查服务会停止；商品配置保持原样。管理菜单同一时间只允许一个终端运行。

## 管理页访问

### SSH 隧道（推荐）

管理页默认只监听本机地址。从自己的电脑建立隧道：

```sh
ssh -N -L 8765:127.0.0.1:8765 your-user@your-server
```

保持 SSH 窗口运行，然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。

### 反向代理域名

使用 Nginx、Caddy 或面板将 HTTPS 域名转发到 `http://127.0.0.1:8765`，并传递原始 `Host`，即可用管理员账号登录。管理页不限制访问域名，无需逐个添加允许列表；旧配置中的 `ADMIN_ALLOWED_HOSTS`（包括 `*`）不再生效，也不会阻止启动。

新安装自动创建管理员并在终端显示一次随机密码。旧安装如果尚无账号，先执行：

```sh
hw init-admin
```

已有账号、旧版密码或自定义账号文件会保留。没有配置账号时，通过域名访问会提示初始化账号；原有本地 SSH 隧道访问仍可使用。忘记密码可执行 `hw passwd`。菜单中的“管理页服务 → 检查管理页账号并重启”也可补建缺失账号。

迁移服务器或更换域名时，只需调整 DNS 和反向代理，无需修改 HostWatch 允许列表。账号仍由新服务器的安装及账号配置管理，导入业务备份不会覆盖管理员账号。旧命令 `hw admin-domain [域名]` 保留兼容，只检查账号并重启服务，不再保存或限制域名。

管理服务继续仅监听本机地址，管理员认证和浏览器跨站请求校验保持启用。通过域名或 SSH 隧道打开管理页时会显示 HostWatch 登录界面，登录成功后使用仅限当前浏览器的 HttpOnly 会话 Cookie；页面右上角可退出登录。旧版 Basic Auth 请求仍兼容，便于已有脚本和反向代理继续使用。

## 在管理页配置 Telegram

管理页的“Telegram 通知”区域可以填写 bot token、chat ID，并临时停用通知。已保存的 token 不会回显；输入框留空表示保留原 token，点击“清除已保存的凭据”按钮并保存配置才会删除它。配置保存在 `/var/lib/vmiss-monitor/config.json`，权限为 `0600`。

保存前可以点击“测试 Telegram”发送一条测试消息。点击“读取最近聊天”会读取 bot 收到的消息，从列表选择 chat ID；如果 bot 使用 webhook，Telegram 不允许读取 updates，此时请直接填写 chat ID。

先在 Telegram 中打开 bot 并发送 `/start`。私聊或群组的 chat ID 可以从 Bot API 查询，也可以先临时在服务器执行：

```sh
sudo -u vmiss-monitor bash -c 'set -a; . /etc/vmiss-monitor.env; set +a; cd /opt/vmiss-monitor; .venv/bin/python monitor.py --show-chat-ids'
```

频道可填写频道用户名（如 `@my_channel`），并确保 bot 是该频道管理员。保存 Telegram 配置后会自动应用到监控服务。

旧版本仍支持 `/etc/vmiss-monitor.env` 中的 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID`，但推荐改用管理页配置。真实 token 不要提交到 GitHub。

## 配置商品

在管理页“商家适配”中选择 VMISS、VPS.SOY、Akile、Isvoro、DMIT、搬瓦工或“其他商家 · 通用 HTTPS 网页”，再点击“添加商品”，会带入对应字段和默认配置。其他商家可使用通用网页规则；开发新增商家预设时，统一在 `admin.js` 的 `merchantPresets` 中维护，新增专用解析仍需实现并注册对应后端适配器。通用网页示例：

```json
{
  "id": "provider-vps-2g",
  "adapter": "html",
  "provider": "ExampleHost",
  "name": "VPS 2 GB",
  "enabled": true,
  "url": "https://shop.example.com/vps-2g",
  "stock_selector": ".stock-status",
  "stock_mode": "availability",
  "available_pattern": "(?i)in stock|available|有货",
  "unavailable_pattern": "(?i)out of stock|sold out|缺货|售罄",
  "purchase_url": "https://shop.example.com/order/vps-2g"
}
```

如果网页显示精确数量，设置 `stock_mode` 为 `quantity`，并将 `stock_pattern` 配置为带捕获组的正则，例如默认的 `([\\d,]+)` 可匹配 `库存 1,203 台` 中的 `1,203`。CSS 选择器必须只匹配一个非空元素；解析不确定时会报错停止，不会把不确定状态当成有货或缺货。

VMISS 商品在管理页设置：

- `aff` 推广 ID，例如 `2762`
- 分类页，例如 `https://app.vmiss.com/store/dedicated-server`
- 商品选择标识：商品卡片 ID（如 `product44`）、完整名称，或订购链接路径末段 slug
- `gid` 或 `pid`，只能填写一个
- 检查间隔，可填写 0–86400 秒的整数；0 表示不额外等待

VMISS 的推广 ID 是可选的全局配置，留空直接打开商品页；通用网页可各自设置购买链接，VPS.SOY 从套餐卡片读取购买链接，Akile 使用接口返回的地区、线路和套餐 ID 生成购买入口。各类商品可以同时监控。

### VPS.SOY：深港IX-MINI

需要手动添加时，打开“VPS 库存通知 → 高级：自定义商品 / 已移出商品”，在“商家适配”选择 VPS.SOY 后点击“添加商品”，会展开已填好以下信息的商品配置：

- 适配器：`VPS.SOY 商品页`
- 地区 / 线路分组：深港 CNIX（FID=`1`、GID=`8`）
- 商品分类页：`https://www.vps.soy/cart?fid=1&gid=8`（与 FID / GID 双向同步）
- 套餐完整名称：`深港IX-MINI`，精确匹配，避免误选 PRO 或其他变体
- 此商品的请求方式：普通 HTTPS 请求；该公开页面目前直接返回库存，无需浏览器服务

先点击“测试通知”，结果直接显示在商品配置内，无需启用自动刷新。确认结果后选择“加入库存监控”或“加入库存通知”，分别设置刷新方式并保存配置。添加的商品默认不参与自动监控，不会因点击快捷添加就启动请求。

监控其他套餐时可再次添加，修改商品名称和“套餐完整名称”，例如 `深港IX-PRO`、`深港IX-Ultra`。VPS.SOY 的 `fid` 选择产品类型、`gid` 选择地区/线路；通过“地区 / 线路分组”快捷选择、手动编辑 FID / GID，或粘贴官网分类页完整地址，字段会双向同步。支持浏览器中的 `https://vps.soy/cart?...`，保存后规范为 `www.vps.soy`。旧配置保留原分类页，不会被默认预设覆盖。

地区下拉选项采用“地区 / 线路（GID）”格式，例如 `日本 · SoftBank（2）`、`深港 · CNIX（8）`；选择常用地区后无需手填 ID。当前 NAT（FID=`1`）分组：深港 CNIX `8`、香港三网直连 `5`、香港 Global `6`、新加坡 Global `4`、日本 SoftBank `2`、日本 IIJ `3`、英国 Global `7`。例如日本 SoftBank 使用 `https://www.vps.soy/cart?fid=1&gid=2`，套餐完整名称填写 `日本软银`。切换分组后必须同时填写目标套餐完整名称，仅修改商品显示名称不会改变匹配条件；今后新增分组可选“自定义地区 / 产品类型”，再填写 FID / GID，以官网实际网址为准。

同一轮内，相同分类地址和请求方式的商品共用一次页面读取，不同 GID 的同名套餐分别检查。测试结果和机器人测试消息显示检查的分类页；匹配不到会提示当前 FID / GID 及本页套餐；请求重定向丢失或改变指定分组时会报错，避免读取其他地区。无需填写 CSS 选择器或 VMISS 推广 ID。

页面显示 `库存：-3` 等负数时按缺货处理，不会误报为 3 件。名称未匹配、库存无法解析，或正库存与售罄标记、禁用购买按钮冲突时会报错；不会将未知状态当作缺货。有货时读取本站真实购买链接，用于提醒中的人工下单入口；缺货时没有可用订购链接则使用商品分类页。

### Akile：HKL-TW

在“商家适配”选择 Akile 后点击“添加商品”，默认添加中国台湾 `TWLite-Mini`，预填线路名称 `TWLite`，指定地区 ID 6，使用普通 HTTPS 请求。已有相同匹配条件的 Mini 商品时会展开已有项，重复点击不会重复添加。新商品默认不参与自动监控，配置会自动展开。需要其他套餐时，可将商品及套餐完整名称修改为目标名称后再添加。

HKL-TW 在网站实际目录中属于台湾分类 `areaId=6`（线路说明为台湾广播 IP、机器位于香港），并不在香港分类 `areaId=3`。快捷添加使用目录中的真实地区；生成的购买链接也指向对应套餐。

HKL-TW 是线路名称，每档套餐分别显示自己的库存，不以系列合计库存代替 Mini 库存。可以在各商品内点击“测试通知”，仅手动刷新或尚未保存时也能测试；然后选择需要监控的套餐、设置刷新方式并保存配置。需要首次检查有货就提醒时，开启“首次启用该商品通知时，有货也发送提醒”；默认首次只记录库存基线。

Akile 商店是动态页面，初始 HTML 不含库存。本适配器读取页面实际使用的公开 GET 接口 `https://api.akile.ai/api/v1/store/GetVpsStoreV3`，无需账号、Cookie、CSS 选择器或推广 ID。相同请求方式的 Akile 商品在每轮共用一次目录读取。支持每个商品覆盖请求方式；默认普通 HTTPS，若选择 FlareSolverr 则解析浏览器返回的 JSON 内容。

监控其他 Akile 套餐时，填写商品显示名称、线路完整名称及套餐完整名称，默认在全部地区中精确匹配线路和套餐（忽略名称首尾空白及英文字母大小写）。官网切换地区后，地址栏可能仍保留最初打开页面的 `areaId`，不能用它判断当前选中的商品。自动识别模式忽略保存的旧地区 ID；没有地区识别方式字段的旧配置升级后也使用自动识别。如果不同地区存在相同的线路和套餐名称，会报匹配不唯一，此时改选“指定地区 ID”缩小范围。

指定地区时，“监控地区（areaId）”通过下拉选择，选项名称后显示对应 ID，例如 `中国澳门（14）`、`中国台湾（6）`、`中国香港（3）`。列表也包含日本、意大利、荷兰、韩国、新加坡、美国、英国、德国和越南；新增地区可选“自定义地区 ID”后输入。已有的指定地区配置会选中对应项，未知 ID 会保留在自定义选项中。

例如监控澳门套餐，线路填写 `MOLite`、套餐填写 `MOLite-高级竞技A`，自动识别实际地区为中国澳门 `14`；若指定地区，必须填写 `14`，而不是旧网址中的台湾 `6`。测试结果及机器人测试消息会显示实际匹配的地区、线路和套餐。购买入口使用目录返回的实际 ID，例如 `https://akile.ai/shop/server?type=traffic&areaId=14&nodeId=38&planId=1017`。接口报错、套餐下架、库存字段缺失或非有效非负整数时会显示错误，不将未知状态当成缺货。打开提醒中的入口后由用户登录并人工下单，不调用下单接口。

确认厂商允许当前访问方式后，选择需要参与自动刷新的商品并点击底部“保存配置”；需要停用时将对应模块改为“仅手动刷新”后再次保存。

### DMIT：按商品 PID 或完整套餐标识监控

在 **VPS 库存大盘 → DMIT** 刷新公开目录，可筛选洛杉矶、香港、东京等实际读取到的地区，选择加入库存监控或库存通知。公开分类入口会自动列入地区/线路下拉框，保留商家的分类名称和 GID。同一 PID 从不同分类添加时仍识别为同一商品。

下架或目录中找不到的套餐可在 **VPS 库存通知 → 高级 → 商家适配 → DMIT** 手动添加：填写包含该套餐的公开分类页，以及购买链接中 `pid=` 后的商品 ID。支持 `https://www.dmit.io/pages/pricing`、`https://www.dmit.io/cart.php?gid=分类ID` 和 `https://www.dmit.io/store/分类路径`。新版价格页通过 `地区:硬件平台:线路:套餐`（例如 `LAX:AS3:PREMIUM:TINY`）区分同名产品。缺货时官网不提供 PID，使用完整套餐标识继续追踪，补货后读取实际 PID；已有 PID 如发生变化会提示核对，避免静默切换商品。大盘自动填写这两个字段，高级添加时至少提供其中一个。显示名称不参与库存识别；不内置可能过时的套餐 PID、价格或数量。

**AFF 管理 → DMIT** 默认使用 `22544`，支持粘贴 `https://www.dmit.io/aff.php?aff=22544`，也可修改或留空。大盘、监控/通知列表和新发出的 Telegram 消息统一使用当前配置的 `aff.php?aff=推广码&pid=商品ID`；留空使用普通商品链接，推广归属以商家规则为准。

DMIT 的 Cloudflare 规则可能拒绝普通请求。在 **网页请求 → DMIT** 配置请求方式并保存后，再刷新大盘或测试通知；大盘仅使用服务器上已保存的请求设置。FlareSolverr 也无法保证通过验证。大盘浏览器请求复用测试所用的串行锁、低内存检查、独立会话及停止后的清理机制；清理失败会明确提示，不会阻塞网页。

**大盘、库存监控、库存通知、手动测试和 VPS 补货抢购共用同一套库存判断**：价格卡片明确缺货则显示缺货；卡片显示有货时，再使用同一请求方式和出口读取该 PID 的购买入口，仅在返回实际商品配置表单时确认有货。购买页提示缺货会覆盖价格卡片的有货状态。此校验只读取页面，不提交订单、不付款；补货抢购仍按其单独配置执行。识别到明确数量时保留数量，否则仅显示有货/缺货，不推测数量。

跳回价格目录、只有常驻购买链接、字段冲突、重复 PID、Cloudflare 校验及 HTTP 错误均不能证明有货。大盘逐项校验：遇到安全验证或浏览器服务故障时停止继续探测，其余待校验商品显示未知；接近本次刷新时间上限时也保留已确认结果，将剩余商品标为未知，可选择地区或单独测试。相同购买入口在同轮、同请求方式、同出口下复用校验结果。升级前未经购买页验证的大盘有货快照显示未知并请求刷新。

监控、通知和运行概览统一采用最新检查结果；DMIT 最近测试失败时显示未知及失败原因，保留历史数据，不将验证失败当成缺货或补货。取消测试不覆盖历史结果。各入口显示的是各自检查时间的快照，库存随时间变化，最终库存、数量和资格以官网实际下单为准。目录整体读取失败仍保留上次快照，已下架商品保留配置等待重新上架。

### 搬瓦工：按套餐、地区 / 机房和计费周期监控

在 **VPS 库存大盘 → 搬瓦工** 刷新目录。页面通过公开的 `catalog.json` 一次读取套餐、地区、机房、规格、价格和布尔库存，不访问购物车或结账页面；地区名称会转换为中文，例如 `美国 · 洛杉矶`、`日本 · 东京`、`中国香港`，机房名称和 ID 仍保留用于区分线路。地区 / 机房分类选项显示套餐类型、机房名称及实际 ID，例如 `美国 · 洛杉矶 · 电商 VPS（USCA_9）`。

同一个 PID 在不同机房或计费周期会生成独立监控项，月付、季付、半年付、年付等周期不会互相覆盖。建议从大盘选择套餐加入库存监控或库存通知；下架套餐也可以在高级商品管理中填写商品页 URL、完整套餐标识和 PID 后继续等待。完整套餐标识由大盘自动填写，格式为 `商品 ID:机房 ID:计费周期:周期价格（美分）`，只用于精确匹配，不会因同名套餐或价格变化静默切换。

搬瓦工的购买链接保留机房、计费周期和配置参数，并统一通过 **AFF 管理 → 搬瓦工** 的推广码（默认 `84938`）生成 `aff.php` 入口；可填写 `84938` 或完整的 `https://bwh81.net/aff.php?aff=84938`，留空则使用普通购买链接。目录和监控请求默认使用普通 HTTPS，也可在 **网页请求 → 搬瓦工** 中选择其他已部署的请求方式。

### Isvoro：按类型、地区/线路、套餐监控

在“商家适配”选择 Isvoro 后添加商品，默认带入 `中国香港（24） → HK PROD（27） → HK PROD MiNi（188）`，使用普通 HTTPS，新商品默认不参与自动监控。三个下拉框分别对应官网的“类型”“地区/线路”“套餐”，括号内显示实际目录 ID。切换类型后必须重新选择线路和套餐；切换线路后必须重新选择套餐，避免保留其他分类的商品。物理机等没有子分类的类型以自身作为地区/线路。

页面内置添加支持时的类型、线路及 HK PROD 套餐名称作为初始选项；点击“刷新 Isvoro 目录”从官网读取最新类型与当前线路套餐，选择其他线路时按需加载其套餐列表。高级商品三层选择的目录读取使用普通 HTTPS，失败会提示并保留已选内容，不会影响页面其他操作。新增或改名商品可刷新目录获取，已经保存的 ID 不会被静默替换为其他套餐。选项名称不代表当前库存，使用“测试通知”读取实时结果；商品未启用或未保存时也可测试。

适配器使用购买页实际使用的公开只读接口：`https://isvoro.com/api/v1/categories`、`/api/v1/categories/{slug}`、`/api/v1/products/{slug}`。按类型、线路、套餐 ID 逐级唯一匹配，并读取商品详情，避免同名套餐串线或只读取分页商品列表的前 20 项。同一轮相同请求方式共用已经读取的目录与详情；普通 HTTPS 和 FlareSolverr 分别缓存。

库存为非负整数时显示数量；接口明确返回 `stock: null` 时表示不限量，只显示“有货”，不伪造具体数量；`ip_available: false` 表示当前无可用 IP，按不可购买处理。接口错误、缺失库存、非法库存、隐藏商品、无购买周期、启用预售或目录归属不符时报告错误，不把未知状态或预售名额当作现货。机器人测试消息及补货通知显示类型、地区/线路和套餐，人工购买入口使用官网的 `/buy/{线路slug}?product={套餐ID}` 定位具体商品。月付/年付是该套餐的购买周期，共享库存，打开官网后自行选择周期和镜像并下单。

## 网页请求与 FlareSolverr

首次安装或更新时自动部署 FlareSolverr，无需另行手动安装。若 `127.0.0.1:8191` 已有就绪服务，安装器直接复用，不改动既有容器。HostWatch 创建的容器名称为 `host-watch-flaresolverr`；重复安装会启动已有容器，保留其镜像和设置，不会强制拉取新镜像或删除其他容器。镜像拉取、端口冲突或启动检查失败会报错，并停止安装流程，不会报告依赖部署成功。

使用已有远端 FlareSolverr 或内存较小、仅需普通 HTTPS 的机器，可显式跳过自动部署：

```sh
curl -fsSL https://raw.githubusercontent.com/xhpx7301/host-watch/main/install.sh -o /tmp/host-watch-install.sh
sudo env HOSTWATCH_INSTALL_FLARESOLVERR=0 bash /tmp/host-watch-install.sh
```

在管理页“网页请求”统一选择全局默认方式和 VMISS、VPS.SOY、Akile、Isvoro、DMIT、搬瓦工、其他商家（通用网页）的独立方式，可选择跟随全局、普通 HTTPS、FlareSolverr 或 cloudscraper。这些设置用于后台自动监控及单次商品测试，保存后生效；单次测试也可使用页面当前未保存的请求设置。新添加的商品跟随商家设置，不再要求逐个选择请求方式。所有商家的大盘刷新同样使用已保存的商家请求方式；旧配置未指定方式时仍默认普通 HTTPS。大盘刷新不会修改通知或监控历史。

配置字段是 `fetcher.provider_modes`，例如 `{"vmiss": "flaresolverr", "akile": "requests", "isvoro": "inherit", "dmit": "cloudscraper"}`。已明确设置的商家方式优先于旧商品的 `request_mode`；`inherit` 表示使用全局默认。升级时缺少商家设置则保留原有商品行为；同一商家旧商品方式不同，界面显示“保留已有商品的不同请求方式”，选择统一方式并保存后覆盖旧差异。旧版客户端保存全局请求字段时会保留已有商家设置。默认仍使用普通 HTTPS，不会遇到拦截就自动切换或反复重试。

cloudscraper 使用 [VeNoMouS/cloudscraper](https://github.com/VeNoMouS/cloudscraper) 的官方 PyPI 发布版 `1.2.71`，通过 `requirements.txt` 在安装和更新时自动安装。使用内置 `native` Python 解释器，无需 Chromium、Docker、Node.js 或额外 API 服务。配置值为 `"cloudscraper"`，例如 `"fetcher": {"mode": "requests", "provider_modes": {"dmit": "cloudscraper"}}`；全局、每商家和旧版每商品配置均支持。网页库存测试使用当前未保存的选择，后台监控、限时秒杀和库存大盘使用已保存设置。

cloudscraper 基于 Requests，能尝试处理其发布版支持的 Cloudflare 校验，不能完整执行网页应用 JavaScript。GitHub 主分支说明可能与 PyPI 发布版功能不同，本项目不依赖主分支未发布的功能；现代托管校验、Turnstile、验证码及站点封禁可能仍无法通过。每次读取使用独立短会话，不复制共享会话中的账号、Cookie 或 Token，也不将验证 Cookie 写回 Telegram 或其他商家的会话。使用内置解释器并限制验证提交次数，不接入付费打码服务；选择此方式不会启动 FlareSolverr，也不使用浏览器渲染等待。单次测试仍可随时停止；失败会给出依赖、网络或校验提示，并保留库存历史，不自动切换其他请求方式。

“网页请求”将 cloudscraper 与 FlareSolverr 的参数和检测分开展示。cloudscraper 的连接超时默认为 10 秒（1–30），读取超时默认为 25 秒（1–120），验证等待默认为 5 秒（0–15，0 表示由库自动识别页面等待时间，仅验证时使用）。配置位于 `fetcher.cloudscraper` 的 `connect_timeout_seconds`、`read_timeout_seconds`、`challenge_delay_seconds`；保存后用于自动监控、大盘、秒杀和单次商品测试。连接/读取超时是各阶段等待限制，不是整个多请求任务的总时长；单次测试进程另有超时保护。

在 **网页请求 → cloudscraper → 测试网站** 选择商家公开目录，或使用 `example.com` 公共 HTTPS 基准页区分基础访问与目标站点问题，点击“测试 cloudscraper 访问”。测试使用当前未保存的 cloudscraper 参数，固定使用 cloudscraper，不受全局或商家方式覆盖；无需启动监控。后台独立进程读取页面，支持立即停止、刷新网页后恢复任务状态，并与商品/秒杀测试共用单任务限制。显示库版本、实际 HTTP 状态、耗时、响应大小、页面标题及地址；Debian 额外显示本次测试进程的峰值内存（不代表整台服务器占用）。不发送 TG、不修改配置或库存/补货记录。页面可读仅证明这个入口访问成功，具体动态接口、分类和商品的库存识别应继续使用“测试通知”。

cloudscraper 无需运行 Chromium，通常比 FlareSolverr 更省 CPU 和内存，1 核 1GB 等小型服务器可优先使用普通 HTTPS，遇到其能处理的验证再尝试 cloudscraper，需要完整页面渲染时再为对应商家选 FlareSolverr。三种方式的实际成功率取决于站点结构和访问规则；FlareSolverr“连接测试”只检测服务就绪，不启动浏览器，因此不能用该测试与一次完整商品读取直接比较资源占用。

FlareSolverr API 默认 `http://127.0.0.1:8191/v1`，超时 10–180 秒。渲染等待支持 0–30 秒，传递官方 `waitInSeconds` 参数，用于页面加载完成后等待动态内容；它是固定额外等待，不会因为确认没有 CF 就提前跳过。默认 0，速度优先时保持 0，只有页面内容不完整时再设为 1–2 秒；普通 HTTPS 和 cloudscraper 不使用此等待。页面提供“轻量加载”和“完整加载”两个互斥选项，默认轻量加载；轻量加载通过官方 `disableMedia` 参数减少图片、CSS 和字体下载，需要服务版本支持该参数，旧版服务可能忽略。若库存读取不完整，切换到完整加载并适当增加等待。超时只是等待上限，降低它不会加快成功请求。优先为可直接读取的商家设置普通 HTTPS 或 cloudscraper，仅在需要浏览器时使用 FlareSolverr；刷新具体分类通常比读取全部分类快。每次浏览器请求使用独立临时会话，由 FlareSolverr 负责关闭，避免跨厂商会话混用和常驻浏览器泄漏；不把浏览器 Cookie 或 User-Agent 写入共享 HTTP 会话。

在 **网页请求 → FlareSolverr → 各商家 FlareSolverr 参数**，可为 VMISS、VPS.SOY、Akile、Isvoro、DMIT、搬瓦工和其他商家分别设置超时、渲染等待、轻量加载。点击对应商家的“参数来源”切换为“独立设置”，初始值取当前默认参数；切回“跟随默认”会移除该商家的覆盖值。独立参数仅在商家实际使用 FlareSolverr 时生效；可提前设置，再在上方选择此商家的请求方式。修改后点击底部“保存配置”，统一应用到大盘、后台监控、库存通知和 VPS 补货抢购；单次商品测试可直接使用未保存的参数。API 地址仍为共享服务地址。

配置字段为 `fetcher.provider_flaresolverr`，例如 `{"dmit":{"timeout_seconds":30,"wait_seconds":0,"disable_media":true},"vmiss":{"timeout_seconds":90,"wait_seconds":3,"disable_media":false}}`。未配置的商家跟随默认 60 秒超时、0 秒渲染等待和轻量加载（或管理员修改后的默认值）。旧版客户端保存请求设置时会保留已保存的商家覆盖值。大盘会显示实际使用的超时、等待和加载方式；参数变更后，上次快照会提示刷新核对。

点击“测试 FlareSolverr 连接”可测试当前未保存的 API 地址并显示版本；此操作不会访问商品网站，也不保证商品页能正常通过验证。实际库存可在“VPS 库存通知”列表点击“测试通知”，也可在高级手动管理中测试：只检查当前商品一次，使用点击时的商品及请求配置，即使未保存、未加入监控或全局监控暂停也能测试。结果直接显示在商品内，包含库存、检查时间、耗时或错误原因；不保存配置、不写入监控历史，也不改变监控开关。修改已完成测试的商品字段后会清除旧提示；测试期间改动配置则在结果中注明使用的是开始时的配置。

单次商品测试完成后会通过已保存的 Telegram Token 和 Chat ID（或服务器环境变量）发送结果，包含商家、商品、库存或错误、检查时间及耗时，检查成功时还附商品入口。缺货也会发送；这是主动测试消息，与“发送测试消息”一样不受自动监控或自动通知开关影响。请先保存机器人配置，页面内尚未保存的机器人修改不会用于本次发送。页面会单独显示“已发送”“未配置”或“发送失败”，发送失败仍保留库存结果；不自动重试，刷新和查询测试状态不会重复发送。停止库存检查不发送结果；检查与浏览器清理完成后进入发送阶段，停止入口禁用，页面仍可操作。

单次测试使用独立后台任务，页面保持可操作；同时只允许运行一个商品测试，商品内及页面顶部均提供“停止测试”。停止会强制结束本次独立子进程，即使进程忽略普通终止信号也会结束；浏览器初始化、库存读取都支持停止。进程创建、信号发送和网络等待不会占用状态锁，避免“停止”和状态查询一起卡住。停止请求不必等待启动请求返回；先停止后到达的启动请求也不会重新启动测试。

浏览器模式通过官方 `sessions.destroy` 清理本次独立会话，正常完成和超时也会清理，不影响其他会话。清理通信在独立进程内执行，启动后最多等待 8 秒，超时强制结束清理进程，再最多等待 2 秒回收。浏览器服务无响应，或停止时远端初始化是否完成尚不确定时，会明确显示“本地测试进程已结束，但未能确认 FlareSolverr 浏览器释放”，不能据此认为远端浏览器已经退出。此时应先检查服务日志、按需重启 FlareSolverr，再进行浏览器测试；默认安装的本机服务可执行 `sudo docker restart host-watch-flaresolverr`（会中断该服务的所有浏览器请求）。

网页直接处理停止接口返回的完成结果，无需等另一个状态请求返回；停止接口暂未完成或状态查询超时时，会恢复“重试停止”入口，不会无限禁用按钮，也不会仅因网页超时就显示已停止。刷新同一浏览器页面会恢复测试状态和停止入口。后台超时会终止本地任务，任务记录仅保留最近 20 项。

Debian 上管理页测试与自动监控共享浏览器请求锁，避免同时启动多个 Chromium；自动监控遇到占用会等待，单次浏览器测试遇到占用直接提示重试。本机 FlareSolverr 启动前检查 `MemAvailable`，低于 256 MiB 时取消启动并提示释放内存或改用普通 HTTPS。此检查不限制 Chromium 后续的内存增长，也不能读取远端 FlareSolverr 的可用内存；约 1 GiB 服务器推荐让 VPS.SOY、Akile、Isvoro 使用预设的普通 HTTPS，将确需浏览器的请求交给资源充足的服务。可在管理员管理区查看监控日志，或在服务器执行：

```sh
sudo docker logs --tail 80 host-watch-flaresolverr
sudo journalctl -u vmiss-monitor.service -n 50 --no-pager
```

请求错误区分 HTTP 403、HTTP 429、Cloudflare 验证页和 FlareSolverr 服务连接/超时/格式错误；Cloudflare 提供 Ray ID 时会展示，便于查询安全事件。使用 `cf-mitigated: challenge` 和验证页特征识别拦截，不再因正常 HTML 包含 `cf-chl-` 脚本就直接误判。服务故障记录为检查失败，网站拒绝访问记录为被拦截，两者均停止等待处理；不会泄露原始浏览器错误中的 Cookie 或 URL 参数。页面最终域名仍需匹配配置的商品域名。

小黄云不等于一定需要浏览器。对于自己的测试站点，建议在 Cloudflare 为监控流量配置合适的规则，FlareSolverr 不能保证通过所有验证。保持 `8191` 仅本机可访问，并仅用于你拥有或获准访问的页面。

管理页采用侧边导航，分为运行概览、VPS 库存大盘、VPS 库存监控、VPS 库存通知、VPS 补货抢购、AFF 管理、网页请求和设置。手机端使用可横向滚动的顶部导航，库存表格可在内部横向滚动。栏目切换带淡入过渡，减少动态效果设置下关闭动画。页面可见时自动刷新后台检查记录与真实服务状态，启动/停止期间每 2 秒、稳定状态每 1 分钟刷新，不访问商家或清除草稿。切换不清除草稿或中断测试；旧 `#products` 链接转至库存通知的高级手动管理。每个可编辑卡片独立保存，只提交该卡片的修改；其他卡片的未保存草稿保留在当前页面。运行、检查、刷新和启停按钮立即执行，不需要先保存；“取消修改”和全局保存栏已移除。

库存监控和库存通知各有独立的自动/手动模式、检查间隔和手动刷新按钮，VPS 补货抢购使用自己的启动/暂停按钮与检查间隔。保存及运行操作会显示处理中并暂时禁用控件，避免重复请求；检查账户、单次商品测试等使用当前表单内容，不要求先保存，运行中的停止按钮始终可操作。结果通过固定浮动提示显示，商品库存测试另有商品内结果。成功提示约 6 秒后收起，失败提示保留到手动关闭。新增、删除或修改会让对应卡片的保存按钮显示未保存状态。保存会自动应用，无需再登录服务器重启；刷新状态只读取最近记录。

## 网页管理员管理

点击左侧导航“管理员管理”进入管理区，可查看服务状态、重启管理页或整台服务器、管理管理员账号，查看最近 100 条服务日志，备份程序和配置，以及从 GitHub 更新 HostWatch。重启服务器会在约 5 秒后执行，当前连接和所有服务会中断，系统恢复后按开机启动配置启动服务。修改密码和删除账号立即生效；不能删除最后一个管理员。添加首个账号后会接管旧认证，后续请求使用新账号登录。网页管理员均具备完整管理权限。

“导出备份”会将程序、配置和账号打包，通过当前浏览器保存到本地；服务器上的临时导出文件会在读取后删除。定时备份、更新前及导入前备份则保存在服务器硬盘 `/var/backups/stockwatch/`，管理页会显示此路径及最近备份。

“导入备份”可上传不超过 20 MB 的 HostWatch `.tar.gz` 备份（兼容原“下载备份”导出的文件），确认后恢复商品及通知配置、出口节点与秒杀设置、库存记录、目录和汇率缓存，以及备份中包含的自动备份计划。当前管理员账号、管理页访问设置和程序版本保持不变，归档内的程序、服务和启动脚本不会执行或覆盖。导入前校验归档路径、大小和配置，并自动备份当前服务器数据；应用失败时尝试回退原数据。完成后监控处于暂停状态，请确认配置后手动启动。导入会替换页面未保存的配置；运行中的商品测试、秒杀或大盘刷新需先停止或等待完成。

如果使用 Nginx 等反向代理，请将上传限制设置为至少 20 MB、请求超时设置为至少 150 秒；Nginx 可在管理页对应的 `server` 中设置 `client_max_body_size 20m;` 和 `proxy_read_timeout 150s;`。

在“自动备份计划”中可用状态按钮开启 / 关闭每日备份，并修改每日执行时间；默认关闭，预设时间为 `03:00`。点击此处“保存备份计划”立即生效，无需底部“保存配置”，也不会重启库存监控或清除其他栏目草稿。时间统一按**北京时间（Asia/Shanghai，UTC+08:00）**执行，页面同时显示下次执行、上次触发及执行结果。计划由 systemd 执行，关闭浏览器或重启管理页不影响；服务器错过计划时，启动后补做一次。关闭定时备份不影响更新前备份和手动下载。

备份计划保存于 `/etc/hostwatch-backup.json`，升级会保留并重新应用，备份包也包含该计划。定时器为 `hostwatch-backup.timer`，执行服务为 `hostwatch-backup.service`；可用 `systemctl list-timers hostwatch-backup.timer` 查看下次执行，或 `journalctl -u hostwatch-backup.service` 查看结果。定时任务和更新 / 网页管理共用操作锁，避免同时打包或更新；卸载会一并移除计划与定时器。

运行概览每分钟刷新一次，显示大盘、监控、通知、抢购的状态、刷新时间和最近日志；四个模块日志默认显示最近 5 条，可隐藏或打开详细日志查看已保存的完整近期记录。顶部右侧显示 HostWatch 管理服务实际运行状态。监控和通知分别选择自动刷新或仅手动刷新；保存对应卡片后自动应用，手动刷新只执行所选模块。每个商品配置均为独立折叠卡片，标题显示名称、厂商和是否参与自动监控；默认收起，新增商品自动展开，日常通知列表提供测试与移出操作；高级表单按需展开。保存及增删其他商品时保留现有展开状态。与当前适配器不相关的字段隐藏。

页面分别显示实际服务运行状态、上次检查结果和未保存修改；概览按大盘、监控、通知、抢购展示模式、间隔、最近刷新时间和独立日志。历史拦截记录会保留至下次检查，不能据此判断服务现在是否运行。库存监控和库存通知可分别选择自动刷新或仅手动刷新，自动间隔支持秒级和分钟级，也可填写 0–86400 秒的整数；间隔是每轮检查完成后的等待时间，0 表示顺序连续检查，不额外等待，也不并发启动多轮。手动刷新只执行所选模块。首次有货提醒适用于没有通知历史或从仅监控转为通知的商品，重启不会清除历史。

从旧版本首次升级仍需在服务器执行一次 `hw update`，以安装网页管理所需的 sudoers 和 systemd 配置；此后可在网页更新。更新先备份，再由独立 systemd 任务执行，管理页短暂中断时页面会等待恢复。备份保存在 `/var/backups/stockwatch/`，包含凭据，仅 root 可访问。

管理服务仍以普通用户运行，sudoers 仅允许固定的 `/usr/bin/python3 /opt/vmiss-monitor/manage.py web-action` 命令；该入口校验固定动作、用户名和参数，不接受任意 shell 命令。管理文件由 root 持有，网页与终端操作共用互斥锁。自定义 `ADMIN_USERS_FILE` 的安装继续通过终端管理账号。

首次检查默认只记录库存基线，不会因已有库存而通知。如需首次发现已有库存也通知，点击开启页面中的对应选项。

## 遇到 Cloudflare 或 HTTP 403

如果 Telegram 收到“VMISS 监控已停止”，或管理页状态显示“因网站拦截已停止”，说明目标网站返回了 Cloudflare 安全验证、HTTP 403 或 HTTP 429。程序会停止当前监控周期，不会连续重试或绕过验证。

处理步骤：

1. 将对应模块改为仅手动刷新，避免反复请求或更换 IP 撞站。
2. 把服务器公网 IP、访问时间和页面截图发给 VMISS，确认允许的监控方式、访问频率和服务器 IP。
3. 获得明确许可后，可先点击商品内“测试通知”；确认正常后保存配置并开启对应模块的自动刷新，再在运行概览查看日志。

如果 VMISS 不允许服务器自动检查，应保持监控关闭，不要尝试绕过 Cloudflare 验证。

## Akile 交易市场

“Akile 交易市场”位于 VPS 补货抢购与网页请求之间。选择已保存的 Akile 网站账户后点击“刷新市场商品”，读取官网登录态市场列表；刷新只读，不发送通知。列表展示实际售价、续费金额/周期、到期时间、剩余天数、基准价值、折价/溢价比例与人民币金额。账户和商家出口沿用现有 Akile 账户配置；密码及登录令牌不会回传浏览器。

基准剩余价值 = 续费金额 × 剩余天数 ÷ 周期天数，月/季/半年/年/两年/三年分别按 30/90/180/365/730/1095 天估算。折价金额 = 基准价值 − 售价；折价率 = 折价金额 ÷ 基准价值 × 100%。溢价取相反数。估值不包含手续费、IP 质量、稀缺性或后续低价续费权利。

商品“添加监控”默认只监控该挂单 ID，也可改为完整套餐名、地区、节点均相同的新挂单。每条规则可设置最低折价或最高溢价：折价达到最低值（≥）触发，溢价低于最高值（≤）触发；折价商品也满足非负的最高溢价限制。比例与金额均可填写，任一满足（OR）为默认，也可选择全部满足（AND）；留空条件不参与判断。零阈值有效。规则修改后点击“保存商品规则”。启用后台监控并保存后，由管理服务按 30–3600 秒间隔顺序检查，关闭网页后继续运行；“检查已保存规则”会立即检查并发送达到阈值的通知。

每条规则按挂单去重，持续满足不重复提醒，读取成功并确认退出条件后再次满足会重新提醒。通知失败或 Telegram 暂停时不记为已发送，恢复后重试。记录位于配置目录下的 `state-akile-market.json`，随备份/恢复保留；损坏时停止触发。分页异常或部分读取失败时保留上次快照，不基于不完整数据触发。数据异常、未知周期、零剩余价值、已到期、拍卖及非在售挂单不触发。

**交易市场自动待付款下单受官方 Passkey 验证限制。** 官网购买流程要求新鲜的 WebAuthn 用户确认，普通 Akile 商店的下单适配不能替代市场购买验证。当前“待付款下单”规则达到阈值后仅发送“需要官网 Passkey 验证，未创建订单”的 Telegram 提醒，不调用 `makeOrder`、支付或余额扣款接口，也不伪造购买验证令牌。需要用户在官网完成购买；待 Akile 提供允许无人值守的下单授权接口后才能实现全自动待付款下单。

## VPS 补货抢购：仅提交待付款订单

从“VPS 库存监控 / VPS 库存通知 → 更多 → 加入 VPS 补货抢购”添加商品，设置数量（默认 1，范围 1–100）、专属优惠码、系统、付款周期、付款方式、账户和出口后保存。系统、付款周期和付款方式会作为待付款订单参数传给商家适配接口；例如 VMISS 的 `US.LA.CMIN2.Elite` 可设置为 `Debian 12`、`monthly`、`alipay`。不会自动减少数量或拆成多笔订单。已知库存数量不足时等待；只提供“有货 / 无货”的商家由下单适配接口最终核验所需数量。下架商品可在高级商品管理中预先添加，配置中移除的商品仅保留手动购买链接。
VMISS 使用内置官网结算适配：登录保存的账户后，自动打开商品配置页，预填系统、付款周期、优惠码和付款方式。提交响应或官网自动跳转到订单 / 账单详情时，优先直接读取该页面确认“未付款”，并核对账单项目中的商品名称、系统和优惠码；只有响应没有可核验详情时，才在不重复提交订单的前提下轮询账单列表，兼容列表状态由样式或属性渲染的页面，再逐张读取详情，直到唯一匹配本次商品的未付款账单出现。不会跟随支付网关、使用账户余额或自动付款。VMISS 商品不再需要额外填写 `hostwatch-unpaid-v1` 接口；若官网出现验证码、二次验证或页面结构变化，任务会停止并提示到官网核对。

Akile 商品使用内置官网下单适配，不需要填写外部下单接口。自动模式会自动勾选服务协议和广播 IP 条款，固定提交 `Debian 12`、1 个月周期和单台数量；提交后还会通过官网订单详情接口核对订单号和 `order_status=1`（待付款），核对成功才停止并发送通知。系统不会调用支付接口，也不会扣余额或访问支付链接，付款由用户登录 Akile 官网核对订单后手动完成。

搬瓦工商品使用内置官网结算适配，不需要填写外部下单接口。自动模式会按商品链接中的机房和付款周期提交结算表单，确认官网返回 `Invoice <编号>: Unpaid` 后才停止并发送通知；支付方式使用商品配置，系统不会访问支付网关、使用账户余额或自动付款。邮箱验证码提交成功后，会在服务进程内短期缓存同一账户、同一出口的认证 Cookie，账户检查和抢购任务会优先复用该会话；缓存只保留 10 分钟，不写入配置和备份，失效后仍需管理员输入最新验证码。

Isvoro 账户支持官网 API 登录检查和短期会话缓存。由于官网登录包含 hCaptcha，首次登录需管理员在 Isvoro 官网手动完成验证，再将浏览器的 Cookie 临时粘贴到账户检查卡片；系统验证 Cookie 对应的邮箱后，仅在服务进程内缓存认证会话 10 分钟，不写入配置或备份。Cookie 失效或服务重启后需重新登录并导入。

- **极速秒杀（自动）**：启动时检查账户，发现一次库存满足要求即提交，减少提交前额外请求；账户或库存可能在提交时变化。
- **精准秒杀（自动）**：启动时检查账户；发现库存后再次认证账户、重新检查库存，仍满足数量才提交。请求更多，可能错过短暂库存，并不保证下单成功。
- **手动秒杀**：只检查一轮并准备购买链接，不提交订单。绑定账户时会尝试检查账户，并显示无法确认的原因。

两种自动模式共用页面设定的检查间隔，含义为每轮结束后的等待时间。启动自动模式后，商品库存满足且账户检查通过就会调用对应商家的内置待付款下单适配；未适配的商家仅提供购买链接。“检查账户”使用已保存的绑定、密码和该商品所选出口，不下单、不付款。检查结果表示本次认证状态，不代表购买资格或库存，验证码、二次验证仍需到官网完成。

每个商品在一次任务中最多发送一次订单请求。内置适配明确返回订单号、所需数量及 `unpaid` 后才显示“已创建待付款订单”；**付款需要你登录商家官网手动完成**。超时、跳转、普通 HTML 或无法确认订单结果时显示“结果待核对”，停止该商品，不自动重试；再次启动前先到官网检查是否已有订单。不同商品各自完成，不因第一个商品下单而停止其他商品。任务运行在管理服务内，服务重启后需重新启动任务。

### 商家登录与下单适配

在“网站账户”选择商家，填写官网登录名 / 邮箱和密码，保存后点击商品旁的“检查账户”。VMISS、VPS.SOY、搬瓦工、DMIT 使用各自官网登录表单适配，自动读取隐藏 CSRF token；Akile 使用官网登录 API，并在读取账户信息、确认邮箱匹配后才判定成功；Isvoro 使用官网登录 API，首次 hCaptcha 需管理员手动完成并导入浏览器 Cookie。凭据只发送到商家的固定 HTTPS 域名，不跟随跨域跳转。启用 FlareSolverr 或 cloudscraper 时，账户检查会先通过同一商家的请求方式获取临时验证状态，再在隔离的登录会话中提交表单。搬瓦工从新出口 IP 登录触发邮箱验证码时，账户卡片会显示验证码输入框，管理员提交最新邮件验证码即可继续原登录会话；验证码和会话只保存在服务进程的短期内存中，不写入配置或备份。其他验证码、二步验证、Passkey 或结构变化会返回未知并提示官网处理。其他商家需要填写实现 `hostwatch-unpaid-v1` 的账户检查 JSON 接口；普通登录 / 结算页面不能直接作为接口。

账户登录检查只验证认证状态，不代表有购买资格或库存，也不创建订单、不付款。邮箱验证码会话默认保留 10 分钟，服务重启或超时后需重新检查账户。支持校验的商家认证 Cookie / API token 也只在服务进程内保留 10 分钟，并按商家、账户和出口隔离，用于后续账户检查及抢购，不写入配置或备份；缓存失效或官网拒绝时会自动重新登录。当前支持内置待付款下单的商家为 VMISS、Akile 和搬瓦工；其他商家暂时不会自动创建订单，只提供购买链接。

不同商品的认证会话与库存请求会话隔离，均走商品所选出口，不自动跟随 HTTP 跳转。内置商家适配必须校验商品、数量、优惠码和购买资格，**仅创建未支付订单，禁止调用支付、余额扣款、保存的银行卡扣款等流程**，并按幂等键去重。

其他商家如需加入自动下单，需要在代码中实现对应的商家专用适配；普通登录页、结算页或通用 URL 不会被当作下单接口调用。账户检查接口仍可用于无法内置登录的商家：

1. 对账户检查接口 `POST` JSON，服务验证账户并设置认证 Cookie：
   ```json
   {"protocol":"hostwatch-unpaid-v1","action":"check_account","username":"user","password":"…"}
   ```
   成功响应必须匹配用户名；失败返回 `authenticated:false` 或 HTTP 401/403，未识别响应按“无法验证”处理：
   ```json
   {"protocol":"hostwatch-unpaid-v1","authenticated":true,"username":"user"}
   ```

## 运维

### Debian / Alpine 出口节点一键安装

在“网页请求 → 出口节点”点击“添加节点”，即可获得节点 ID、名称、8787 监听端口等默认值。点击“一键复制安装命令”会保存当前节点并生成随机代理令牌，其他栏目的未保存草稿保持原样；无需手动修改默认配置。将命令在子服务器以 root 执行（普通用户已配置 sudo 时也可执行）。脚本支持 Debian 12/13 的 systemd 和 Alpine 的 OpenRC，自动安装 Python 和 requests，创建专用服务用户，并设置开机启动。

已有节点默认收起，点击名称或左侧箭头可展开安装命令和详细配置，新添加的节点自动展开。公网 IP 显示在名称旁，启停、检查出口 IP 和移除节点位于标题栏右侧；收起时仍可操作，刷新或检查 IP 会保留当前展开状态。

安装后自动识别子服务器公网 IP，并以该节点的独立令牌回报当前管理页地址；点击“刷新节点”即可获取代理地址和健康检查地址，然后在“商家出口路由”选择节点并保存配置。主服务器必须能够访问子服务器的监听端口（默认 TCP 8787）；节点只有完成连接信息回填后才能用于请求，未就绪或失效时不会回退主服务器直连。

出口路由按商家生效，未绑定商家使用主服务器直连；大盘刷新、库存监控/通知、Isvoro 分类读取和网页访问测试均继承对应商家已保存的出口。网页测试可以临时测试请求方式，但出口使用已保存配置；VPS 补货抢购可为商品单独指定节点。商家官网购买链接由你自己的浏览器打开，不经过服务器出口。FlareSolverr 会在创建浏览器会话时设置节点代理及认证，主服务访问 FlareSolverr 控制接口不经过该节点。

“检查出口 IP”会先检查节点身份，再通过该节点的认证代理建立 HTTPS 隧道、验证 TLS 证书，并从公网 IP 检测服务读取实际出口 IP；只访问节点 `/health` 成功不会再显示成代理验证成功。IP 检测优先使用 api.ipify.org，站点不可用时尝试 ifconfig.me/ip；检测站点均不可达时会明确提示未验证代理可用。HTTP 407 表示代理认证失败，HTTP 502 表示节点无法连接目标站点。主服务升级后即可修复 HTTP / cloudscraper 代理地址缺少密码分隔符、未发送认证的问题，已安装的节点无需重装；只有令牌不一致时才需在子服务器重新执行该节点安装命令。

大盘显示商家已保存的请求方式、节点名称和最近检查的出口 IP；未保存修改会单独提醒，刷新任务固定使用启动时配置。快照保留采集时的出口信息，切换出口不会自动把历史数据视为新出口结果，需手动刷新核对。节点停用、未回报或缺少令牌时会显示失败原因，不会显示成“该分类暂无公开套餐”；已有快照保留供参考。节点 IP 是最近回报/检查值，不是每次商品请求实时探测值。

如果管理页通过 `127.0.0.1` / `localhost` SSH 隧道访问，安装命令会自动关闭远程回报。复制安装完成后终端输出的 JSON，粘贴到该节点的“回填安装结果”并提交，即可自动设置地址和 IP，无需手动编辑字段。公网管理地址回报失败时也可使用此入口。节点未被复制命令保存、已删除或令牌不匹配时，安装结果不会被接受。

子服务器程序安装在 `/opt/hostwatch-egress/`，配置和令牌保存在 `/etc/hostwatch-egress.json`（仅 root 和节点服务用户可读取）。服务名称为 `hostwatch-egress-agent`：Debian 使用 `systemctl status hostwatch-egress-agent` / `journalctl -u hostwatch-egress-agent`；Alpine 使用 `rc-service hostwatch-egress-agent status`，日志位于 `/var/log/hostwatch-egress.log`。重复执行安装命令会更新并重启同一服务，不会重复创建节点。安装命令和回填 JSON 包含该节点令牌。

每个节点旁还提供“一键复制卸载命令”，所有节点使用同一条命令，无需节点 ID 或令牌；复制不会保存或修改配置。请在需要卸载的子服务器以 root 执行（支持 sudo），自动识别 Debian / Alpine，停止服务、取消开机启动，删除节点程序、配置、Alpine 日志及专用服务账户，不移除共享 Python 依赖或主服务数据。新安装的节点优先运行本地 `/opt/hostwatch-egress/uninstall.sh`，无需联网；旧节点会自动下载卸载脚本。也可直接执行 `sudo sh /opt/hostwatch-egress/uninstall.sh`。卸载后，在主服务管理页调整使用该节点的商家/秒杀出口，点击“移除节点”并保存配置；管理页移除记录不会远程卸载子服务器程序。

```sh
sudo systemctl status vmiss-monitor-admin.service vmiss-monitor.service
sudo journalctl -u vmiss-monitor.service -f
sudo journalctl -u vmiss-monitor-admin.service -f
```

程序安装在 `/opt/vmiss-monitor/`；配置和状态在 `/var/lib/vmiss-monitor/`；兼容用 Telegram 环境文件在 `/etc/vmiss-monitor.env`；反向代理访问设置在 `/etc/vmiss-monitor-admin.env`。

停止服务：

```sh
sudo systemctl disable --now vmiss-monitor.service
sudo systemctl disable --now vmiss-monitor-admin.service
```

## 升级

在网页管理员管理区点击“更新 HostWatch”，或在服务器运行 `hw update`。升级不会覆盖商品、Telegram 或管理员配置；更新前自动备份，成功后恢复原来正在运行的监控。网页更新启动后约 10 秒自动刷新管理页，并恢复刷新前所在的栏目。手动刷新浏览器也会保留当前栏目。旧版本首次升级请先运行一次 `hw update`。
