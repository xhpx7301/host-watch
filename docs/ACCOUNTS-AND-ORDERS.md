## 商家登录与抢购能力

账户检查成功只表示本次认证通过；库存监控、账户登录、余额通知和自动下单是分别适配的功能。下表中的自动抢购均只创建待付款订单，付款需到官网手动完成。

| 商家 | 登录 / 认证方式 | 内置自动抢购 | 范围与限制 |
| --- | --- | --- | --- |
| VMISS | 官网账号密码 + Remember Me；可导入 Cookie 后验证 | 已适配 | 官网结算创建待付款发票；遇安全验证需人工处理 |
| Akile | 官方 API 登录 + 账户令牌校验 | 已适配 | 普通商店商品，固定 Debian 12、1 个月周期；二手市场受 Passkey 限制，仅提醒 |
| 搬瓦工 | 官网账号密码 + Remember Me；支持邮箱验证码及 Cookie 导入 | 已适配 | 官网结算创建未付款账单 |
| Isvoro | 官网完成 hCaptcha 后导入 Cookie，支持官方 refresh Cookie | 已适配 | 普通商品，使用 Debian12 / 支付宝；二手市场仅提醒 |
| DMIT | 官网账号密码 + Remember Me，或 Cookie + User-Agent | 适配未完成，暂不可用 | 实际自动下单尚不能成功；库存监控、通知和账户检查可独立使用，请到官网手动下单 |
| VPS.SOY | 已内置官网账号密码登录检查 | 未内置适配 | 库存监控、提醒和手动购买；自动模式会提示未适配 |
| 独角鲸云 | 邮箱密码 API + Bearer 令牌，核对账户邮箱 | 未内置适配 | 库存监控、账户检查、余额通知和手动购买 |
| Hytron | 邮箱密码 API + Bearer 令牌，核对账户邮箱 | 未内置适配 | 节点资源监控、账户检查、余额通知和手动购买 |
| 其他 / 通用网页 | 登录检查需单独实现商家接口 | 未内置适配 | 通用网页库存监控不代表支持账户登录或下单；兼容下单接口需开发并校验能力 |

DMIT 虽有下单适配代码，但尚未完成实际下单验证，不能视为可用的自动抢购功能；账户检查或配置测试通过也不代表可以成功下单。请使用手动模式在官网下单，Debian 与 Docker 均适用。

未内置适配的商家请选择**手动抢购**，自动模式会阻止提交并提示未适配。填写普通登录页或购买链接不会自动获得下单能力，Debian 与 Docker 的商家适配范围相同。

### Hytron 登录与余额通知

1. 在“网站账户”添加账户，商家选择 **Hytron**，填写官网注册邮箱和密码，单独保存该账户。
2. 点击“检查账户”。服务向 Hytron 官方 API 提交邮箱和密码，取得 Bearer 令牌后读取账户资料，核对邮箱一致才判定认证成功；不用填写自定义接口。
3. 需要余额提醒时，在“账户余额通知 → Hytron”选择该已保存账户，设置阈值和检查频率后保存。余额以美元显示；公开节点资源监控无需账户。

Hytron 暂不提供 Cookie 或 API 令牌手动导入。认证会话按商家、账户、密码和出口节点隔离，最长缓存 30 天，在服务器本地以独立密钥加密保存；服务重启后恢复并先复核有效性，商家令牌实际有效期仍以官网为准。令牌无效时会尝试正常邮箱密码登录；遇验证码、二步验证或 API 异常时到官网人工处理。修改账号、密码或出口后需重新检查。认证缓存不随普通业务备份导出。

**Hytron 登录和余额通知已接入，自动抢购尚未适配。** 账户认证通过后也不会自动创建 Hytron 虚拟机或订单。

## 二手交易市场与通知

“二手交易市场”和“二手市场通知”分别位于左侧导航。交易市场页选择市场及已保存的网站账户后点击“刷新市场商品”，读取官网登录态市场列表；刷新只读，不发送通知。列表展示实际售价、续费金额/周期、到期时间、剩余天数、续费月付基准、折价/溢价比例与人民币金额。账户和商家出口沿用现有账户配置；密码及登录令牌不会回传浏览器。通知页独立设置后台检查开关、间隔和指定商品规则，也可测试通知或立即检查已保存规则；两页的市场及账户选择保持同步。

“账户余额通知”位于二手市场通知下方，目前接入独角鲸云和 Hytron。每个商家可以单独选择监控账户、开启后台监控、设置 30–3600 秒检查间隔、低余额阈值，以及低余额和余额变化通知条件；页面使用按钮选择，不使用勾选框。独角鲸云余额按人民币 `¥` 显示，Hytron 余额按美元 `$` 显示；两个商家的账户、检查周期和阈值互不影响。也可点击“立即检查”读取页面上选中的账户。提醒去重和失败重试状态保存在配置目录的 `state-account-balance.json`，备份/恢复会一并保留；账户读取失败不会覆盖最近一次成功余额。Telegram 通知已独立为左侧导航选项，可为余额、库存、抢购和二手市场通知分别指定机器人。

剩余价值 = 周期续费金额 × 剩余天数 ÷ 周期天数；折价/溢价金额先与剩余价值比较。比例以续费月付价为基准，续费月付价 = 续费金额 ÷ 续费周期月数，年付按 12 个月折算。折价率 = 折价金额 ÷ 续费月付价 × 100%，溢价率同理。到期时间用于计算剩余价值和过滤已到期挂单。估值不包含手续费、IP 质量、稀缺性或后续低价续费权利。

商品“添加监控”默认只监控该挂单 ID，也可改为完整套餐名、地区、节点均相同的新挂单。每条规则可设置最低折价或最高溢价：折价达到最低值（≥）触发，溢价低于最高值（≤）触发；折价商品也满足非负的最高溢价限制。比例与金额均可填写，任一满足（OR）为默认，也可选择全部满足（AND）；留空条件不参与判断。零阈值有效。规则修改后在“二手市场通知”页保存。启用后台监控并保存后，由管理服务按 30–3600 秒间隔顺序检查，关闭网页后继续运行；“检查已保存规则”会立即检查并发送达到阈值的通知。

每条规则按挂单去重，持续满足不重复提醒，读取成功并确认退出条件后再次满足会重新提醒。通知失败或 Telegram 暂停时不记为已发送，恢复后重试。记录位于配置目录下的 `state-akile-market.json`，随备份/恢复保留；损坏时停止触发。分页异常或部分读取失败时保留上次快照，不基于不完整数据触发。数据异常、未知周期、零月付基准、已到期、拍卖及非在售挂单不触发。

单条挂单规则还会持续核对市场状态：Akile 使用挂单详情接口，Isvoro 使用完整市场分页结果。首次成功检查仅建立“仍在市场 / 已下架”基线；后续确认下架或重新上架时发送包含配置和挂单 ID 的库存状态通知。请求失败、详情无法确认或分页不完整时显示“状态未知”，不会误报下架。状态记录分别保存在配置目录下的 `state-akile-market-presence.json` 和 `state-isvoro-market-presence.json`。

**交易市场自动待付款下单受官方 Passkey 验证限制。** 官网购买流程要求新鲜的 WebAuthn 用户确认，普通 Akile 商店的下单适配不能替代市场购买验证。当前“待付款下单”规则达到阈值后仅发送“需要官网 Passkey 验证，未创建订单”的 Telegram 提醒，不调用 `makeOrder`、支付或余额扣款接口，也不伪造购买验证令牌。需要用户在官网完成购买；待 Akile 提供允许无人值守的下单授权接口后才能实现全自动待付款下单。

同一页面也可切换到 **Isvoro 二手市场**。选择已保存的 Isvoro 网站账户读取市场挂单，列表展示实际售价、续费周期、到期时间和续费月付基准；可按单条挂单或相同套餐、地区和节点设置折价/溢价 Telegram 提醒。账户会话沿用 Isvoro 网站账户的现有验证与内存缓存；若官网要求 hCaptcha，请先在官网完成验证并导入 Cookie。只读刷新不会买入，后台规则也只发送提醒，不提交订单、不付款。金额比较仅在售价与续费币种相同时启用；周期未知、数据异常或已到期的商品不触发。

## VPS 补货抢购：仅提交待付款订单

从“VPS 库存监控 / VPS 库存通知 → 更多 → 加入 VPS 补货抢购”添加商品，设置数量（默认 1，范围 1–100）、专属优惠码、系统、付款周期、付款方式、账户和出口后保存。系统、付款周期和付款方式会作为待付款订单参数传给商家适配接口；例如 VMISS 的 `US.LA.CMIN2.Elite` 可设置为 `Debian 12`、`monthly`、`alipay`。不会自动减少数量或拆成多笔订单。已知库存数量不足时等待；只提供“有货 / 无货”的商家由下单适配接口最终核验所需数量。下架商品可在高级商品管理中预先添加，配置中移除的商品仅保留手动购买链接。
VMISS 使用内置官网结算适配：登录保存的账户后，自动打开商品配置页，预填系统、付款周期、优惠码和付款方式。提交响应或官网自动跳转到订单 / 账单详情时，优先直接读取该页面确认“未付款”，并核对账单项目中的商品名称、系统和优惠码；只有响应没有可核验详情时，才在不重复提交订单的前提下轮询账单列表，兼容列表状态由样式或属性渲染的页面，再逐张读取详情，直到唯一匹配本次商品的未付款账单出现。不会跟随支付网关、使用账户余额或自动付款。VMISS 商品不再需要额外填写 `hostwatch-unpaid-v1` 接口；若官网出现验证码、二次验证或页面结构变化，任务会停止并提示到官网核对。

Akile 商品使用内置官网下单适配，不需要填写外部下单接口。自动模式会自动勾选服务协议和广播 IP 条款，固定提交 `Debian 12`、1 个月周期和单台数量；提交后还会通过官网订单详情接口核对订单号和 `order_status=1`（待付款），核对成功才停止并发送通知。系统不会调用支付接口，也不会扣余额或访问支付链接，付款由用户登录 Akile 官网核对订单后手动完成。

搬瓦工商品使用内置官网结算适配，不需要填写外部下单接口。自动模式会按商品链接中的机房和付款周期提交结算表单，确认官网返回 `Invoice <编号>: Unpaid` 后才停止并发送通知；支付方式使用商品配置，系统不会访问支付网关、使用账户余额或自动付款。邮箱验证码提交成功后，会将同一账户、同一出口的认证 Cookie 使用服务器本地独立密钥加密保存，服务重启或代码更新后自动恢复并先复核有效性；加密缓存不写入业务配置、GitHub 或普通业务备份。Cookie 失效、账户/密码/出口变化或商家撤销会话后仍需重新输入最新验证码。

Isvoro 账户支持官网 API 登录检查。由于官网登录包含 hCaptcha，首次登录需管理员在 Isvoro 官网手动完成验证，再将浏览器的 Cookie 临时粘贴到账户检查卡片；系统验证 Cookie 对应的邮箱后，会使用服务器本地独立密钥加密保存认证会话，服务重启或代码更新后自动恢复并先复核有效性。加密缓存不写入业务配置、GitHub 或普通业务备份；Cookie 失效、账户/密码/出口发生变化或商家撤销会话后仍需重新登录并导入。

- **极速秒杀（自动）**：启动时检查账户，发现一次库存满足要求即提交，减少提交前额外请求；账户或库存可能在提交时变化。
- **精准秒杀（自动）**：启动时检查账户；发现库存后再次认证账户、重新检查库存，仍满足数量才提交。请求更多，可能错过短暂库存，并不保证下单成功。
- **手动秒杀**：只检查一轮并准备购买链接，不提交订单。绑定账户时会尝试检查账户，并显示无法确认的原因。

自动模式使用对应商家设定的检查间隔，含义为同一商家下一次检查前的等待时间。商品库存满足且账户检查通过后，系统才会调用对应商家的内置待付款下单适配；未适配的商家请选择手动模式使用购买链接；自动模式会提示未适配。“检查账户”使用已保存的绑定、密码和该商品所选出口，不下单、不付款。检查结果表示本次认证状态，不代表购买资格或库存，验证码、二次验证仍需到官网完成。

每个商品在一次任务中最多发送一次订单请求。内置适配明确返回订单号、所需数量及 `unpaid` 后才显示“已创建待付款订单”；**付款需要你登录商家官网手动完成**。超时、跳转、普通 HTML 或无法确认订单结果时显示“结果待核对”，停止该商品，不自动重试；再次启动前先到官网检查是否已有订单。不同商品各自完成，不因第一个商品下单而停止其他商品。任务运行在管理服务内，服务重启后需重新启动任务。

### 商家登录与下单细节

在“网站账户”选择商家，填写官网登录名 / 邮箱和密码，保存后点击商品旁的“检查账户”。VMISS、VPS.SOY、搬瓦工、DMIT 使用各自官网登录表单适配，自动读取隐藏 CSRF token；独角鲸云、Hytron 和 Akile 使用官网登录 API，并在读取账户信息、确认邮箱匹配后才判定成功；Isvoro 使用官网登录 API，首次 hCaptcha 需管理员手动完成并导入浏览器 Cookie。凭据只发送到商家的固定 HTTPS 域名，不跟随跨域跳转。启用 FlareSolverr 或 cloudscraper 时，账户检查会先通过同一商家的请求方式获取临时验证状态，再在隔离的登录会话中提交表单。搬瓦工从新出口 IP 登录触发邮箱验证码时，账户卡片会显示验证码输入框，管理员提交最新邮件验证码即可继续原登录会话；验证码和会话只保存在服务进程的短期内存中，不写入配置或备份。其他验证码、二步验证、Passkey 或结构变化会返回未知并提示官网处理。其他商家需要填写实现 `hostwatch-unpaid-v1` 的账户检查 JSON 接口；普通登录 / 结算页面不能直接作为接口。

账户登录检查只验证认证状态，不代表有购买资格或库存，也不创建订单、不付款。邮箱验证码会话默认保留 10 分钟，服务重启或超时后需重新检查账户。商家认证 Cookie / API token 最长缓存 30 天，按商家、账户和出口隔离，并使用服务器独立密钥加密保存；重启后恢复并复核有效性，不写入业务配置或普通业务备份。缓存失效时尝试正常登录或受支持的官方 refresh；人工验证仍需在官网完成。当前内置待付款下单已适配 VMISS、Akile、搬瓦工和 Isvoro 普通商品；DMIT 下单适配尚未完成，实际自动下单暂不可用，请使用手动模式；其他商家请使用手动模式，自动模式会提示未适配。

不同商品的认证会话与库存请求会话隔离，均走商品所选出口，不自动跟随 HTTP 跳转。内置商家适配必须校验商品、数量、优惠码和购买资格，**仅创建未支付订单，禁止调用支付、余额扣款、保存的银行卡扣款等流程**，并按幂等键去重。

其他商家如需加入自动下单，需要在代码中实现对应的商家专用适配；普通登录页、结算页或通用 URL 不会被当作下单接口调用。账户检查接口仍可用于无法内置登录的商家：

1. 对账户检查接口 `POST` JSON，服务验证账户并设置认证 Cookie：
   ```json
   {"protocol":"hostwatch-unpaid-v1","action":"check_account","username":"user","password":"…"}
   ```
   成功响应必须匹配用户名；失败返回 `authenticated:false` 或 HTTP 401/403，未识别响应按“无法验证”处理：
   ```json
   {"protocol":"hostwatch-unpaid-v1","authenticated":true,"username":"user"}
   ```
